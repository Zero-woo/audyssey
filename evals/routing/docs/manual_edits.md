# 명령 설명 수동 수정 기록

사람(이번에는 Claude가 그 역할)이 **train 실패만 보고** `descriptions.json`을 고칩니다. 효과는 dev로만 확인합니다. 나중에 자동 개선 루프를 만들면 이 기록이 비교군이 됩니다.

## v2 → v3 (2026-11-18)

**근거:** Qwen2.5-3B train 기준선(`runs/2026-11-18_baseline-qwen2.5-3b-train`)에서 95문제 중 52문제를 틀렸습니다.

| 고친 곳 | 이유 (train 실패 유형) |
|---|---|
| `none`, `clarify` | **모순 제거.** `none`에 "지원하지 않는 편집은 clarify unsupported"라고 적혀 있어서, 자막·배속·화면 밝기를 `none`으로 둔 평가셋 기준과 충돌했습니다. `none`에 "오디오가 아닌 기능(자막, 자르기, 배속, 화면 효과)"을 적고, `clarify unsupported`는 "할 수 없는 오디오 편집"으로 좁혔습니다. Gemini가 dev에서 틀린 3개 중 2개가 이 경계에서 나왔습니다. |
| `set_pitch` | **예시 값 따라 쓰기.** "한 키 올려" 요청에 항상 3을 냈습니다. 예시를 "pitch 0, 반음 내려 → −1"과 "pitch 1, 두 키 올려 → 3" 두 개로 바꾸고, 계산식(현재 + 변화량, 내리면 음수)을 적었습니다. |
| `set_gain` | 계산식(현재 gain × 배수)을 적고, 현재 gain이 1이 아닌 예시(0.3 × 2 = 0.6)를 넣었습니다. |
| `keep`, `drop`, `set_gain` | **residual 지칭 실패.** "나머지 소리", "남은 소리", "분리 안 된 소리"가 `residual`이라고 적었습니다. "음소거해줘"는 drop, 음소거를 푸는 요청은 keep이라고 적었습니다(gain 0이나 1이 아님). |
| `reseparate`, `generate` | **제약 무시.** 할 수 없는 경우(생성 소스·무음 영상의 재분리, 대사 생성, residual)를 `when` 안으로 옮겼습니다. |
| `add_source`, `generate` | **새 소리 추가와 기존 소스 교체의 혼동.** 기준을 "job에 있는 소스를 바꾸면 generate, job에 없는 소리를 더하면 add_source"로 적었습니다. "원본에 들리지만 아직 분리하지 않은 소리면 separate"도 넣었습니다. |
| `render` | "인코딩해줘", "최종본 뽑아줘"를 넣었습니다. |

**결과 (Qwen2.5-3B, k=5):**

| 지표 | train | dev |
|---|---|---|
| macro-F1 | 0.627 → 0.686 | **0.553 → 0.625** |
| none 억제율 | | 0.67 → 1.00 |
| pass^5 | | 0.47 → 0.64 |
| invalid 비율 | | 0.096 → 0.096 |

- **명령별 recall (dev):** 떨어진 명령은 없습니다. keep 0.57 → 0.71, reseparate 0.80 → 1.00, render 0.75 → 1.00, none 0.67 → 1.00.
- **채택 규칙** (dev macro-F1 상승, 3%p 넘게 떨어진 recall 없음, none 억제율 유지 이상): 모두 통과했습니다.
- **남은 약점:** clarify와 add_source의 recall은 여전히 0입니다. 소형 모델이 동사에 맞는 명령을 고르는 경향이 강해서, 되묻기와 제약 조건을 따르지 않습니다. 설명만으로는 한계가 있어 자동 개선 루프에서 다룰 과제로 남겨 둡니다.
- **아직 보지 않은 것:** test는 열지 않았습니다. Gemini가 v3에서 떨어지지 않는지(회귀)도 아직 확인하지 않았습니다.

### 같은 v3 설명, 모델만 키운 경우: Qwen2.5-7B (2026-11-18)

| 지표 (dev) | Qwen2.5-3B v3 | Qwen2.5-7B v3 |
|---|---|---|
| macro-F1 | 0.625 | **0.755** |
| pass^5 | 0.64 | 0.74 |
| 되묻기 적중률 | 0.22 | 0.33 |
| 지연 중앙값 | 0.12초 | 0.28초 |

- **오른 것:** add_source recall이 0 → 1.00, keep이 0.71 → 0.86입니다. "새 소리 추가"와 "기존 소스 교체"를 구분하는 일은 모델 크기로 풀렸습니다.
- **떨어진 것:** drop recall이 0.92 → 0.85, render가 1.00 → 0.75입니다. 각각 1문제 차이입니다(x-052 "나머지 소리만 빼주세요" → keep, g-031 "오디오 합성해서 영상 추출" → 복합 요청으로 오인).
- **그대로 남은 것:** dev에서 틀린 19개 중 14개가 되묻기 6, 실행 불가 6, 복합 2입니다. 3B와 같은 약점이라, 모델을 키워도 "하지 않아야 할 때"를 알아채는 문제는 남습니다.
- **train:** macro-F1 0.803입니다.
